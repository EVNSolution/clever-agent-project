Architecture · CLEVER Agent Project

Three-repo control plane, down to the directory level

이 버전은 repo 역할만 보여주는 다이어그램이 아니라, 각 저장소 안에서 어떤 디렉터리가 실제로 시작점, 정본, ledger, handoff를 담당하는지까지 한 화면에 내려서 보여준다.

EntryUser session opens the line
Start Surface`clever-agent-project` intake and bootstrap
Interpretation`clever-context-monorepo` rules, lineage, service docs
Ledger`clever-change-control` root and scoped trace
ExecutionTarget repo implements, tests, ships

Start Surface

clever-agent-project

01

사용자 요청을 intake하고, 쉬운 시작 템플릿을 적용한 뒤 bootstrap packet과 handoff 방향을 잡는 레포다.

/README.md

  • 세션 시작 템플릿 노출
  • 사용자가 가장 먼저 보는 entry 문서

/.agent/skills/bootstrap-clever-work/

  • `SKILL.md`: 시작 규칙과 hard gate
  • `scripts/bootstrap_clever_work.py`: bootstrap packet 생성 로직
  • `agents/openai.yaml`: agent 연결 설정

/docs/

  • `setting.md`: 운영 설명서
  • `guides/`: project workflow 가이드
  • `templates/`: issue 편집 템플릿
  • `diagrams/`: 현재 보는 구조/흐름 다이어그램
  • `superpowers/`: plan/spec 기록

/scripts + /tests

  • `scripts/bootstrap_clever_work.py`: CLI 진입점
  • `scripts/sync_issue_from_md.py`: issue sync helper
  • `tests/test_bootstrap_clever_work.py`: bootstrap 규칙 검증

Interpretation SSOT

clever-context-monorepo

02

전역 규칙과 템플릿 계보, 서비스 문맥, deploy baseline을 가진 해석 정본이다. 코드 저장소라기보다 문맥 저장소에 가깝다.

/docs/root/

  • `index.md`: 읽기 시작점
  • `authority-boundaries.md`: start / interpret / trace 경계
  • `agent-runtime-governance.md`: agent 동작 규칙
  • `template-harness-governance.md`: lineage 선택 기준
  • `deploy-template-governance.md`, `pipeline-governance.md`: 운영 baseline

/docs/services/

  • `service-template.md`: 서비스 문서 스키마
  • `service-*/index.md`: 서비스별 lineage / deploy profile / source mirror
  • `index.md`: 서비스 문서 진입점

/docs/templates/ + /templates/deploy/

  • `docs/templates/index.md`: template registry
  • `msa-template/`, `test-erik-project-template/`: template family 문맥
  • `templates/deploy/`: 배포 템플릿 skeleton과 override 가이드

/docs/wiki/ + /apps /packages /services /contracts

  • `docs/wiki/`: 탐색용 입구, 정본 아님
  • `contracts/`: 공통 계약 기준점
  • `apps`, `packages`, `services`: 현재는 placeholder 구조

Root + Scoped Trace

clever-change-control

03

`project-start` root, scoped change, rollout/rollback evidence를 묶는 ledger 저장소다. 규칙 정본을 소유하지는 않는다.

/README.md

  • root canonical identifier와 `change_id` 규칙 설명
  • MSA/SaaS vs 일반 개발 타입 체계 설명

/.github/ISSUE_TEMPLATE/

  • `project-start`, `change request`, `rollback` template 자리
  • 실제 운영 폼이 들어갈 issue template 레이어

/changes/

  • change unit별 기록 anchor
  • linked repo / PR / status를 묶는 위치

/releases/dev · /stg · /prod

  • 환경별 release evidence 정리 위치
  • rollout / rollback trace를 남기는 곳

Execution Surface

Target Repo

EXT

실제 구현, 테스트, 빌드, 배포 설정은 여기에서 일어난다. control-plane 3레포는 이 저장소를 해석하고 추적할 뿐, 대체하지 않는다.

/src or /app

  • 비즈니스 구현 코드
  • 서비스 API / UI / domain logic

/tests + /.github or deploy config

  • 검증 코드와 CI
  • build-only 또는 runtime-specific deploy assets

/docs or local specs

  • 서비스 구현 문맥의 로컬 보조 문서
  • 최종 authority는 여전히 context/change-control과 연결
Start surface
`README.md`, `.agent/skills/`, `/docs`, `/scripts`가 세션을 열고 packet을 만든다.
Interpretation SSOT
`docs/root`, `docs/services`, `docs/templates`가 rule과 lineage를 해석한다.
Ledger
`README`, `.github/ISSUE_TEMPLATE`, `changes`, `releases`가 root/scoped trace를 남긴다.
Execution
실제 코드와 테스트는 target repo에서만 수행된다.
