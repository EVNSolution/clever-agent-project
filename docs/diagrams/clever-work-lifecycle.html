Swimlane · CLEVER Agent Project

Session start to target-repo execution, with directory anchors

단계만 보여주는 흐름도가 아니라, 각 actor가 실제로 어느 레포의 어느 디렉터리와 파일을 읽고 쓰는지까지 포함한 실행 다이어그램이다.

Stage 1Open the request
Stage 2Pass the hard gate
Stage 3Interpret with SSOT
Stage 4Draft the root line
Stage 5Approve and anchor
Stage 6Fix scoped execution
Stage 7Implement in target repo
USER

User / 01

Open a session in `clever-agent-project`

  • entry through `/README.md`
  • free text or copied start template

User / 02

Fill the easy start template

  • `작업 성격: 신규 개발 / 기존 기능 확장·수정 / 버그 수정 / 리팩터링 / 문서·운영 정리`
  • `대상 범위: 앱·서비스·기능 / 화면·UI / API / DB·model / CI·CD / 문서·운영 설정`
  • `목표 수준: 요구사항 / 설계 / 계획 / 코드 변경 / 테스트 / 배포·운영`
  • 현재 상태, 알려진 링크, 주의사항은 아는 만큼만 입력

User / 03

Approve the `project-start` draft

  • root line을 열어도 되는지 승인
  • candidate repo/service 검토
AGENT PROJECT

Agent / 01

Normalize the opening request

  • `/README.md`
  • `/docs/setting.md`

Agent / 02

Enforce the hard gate

  • `/.agent/skills/bootstrap-clever-work/SKILL.md`
  • `/docs/guides/clever-project-workflows.md`

Agent / 03

Read context and choose candidate lineage

  • context repo root and services docs
  • template registry and deploy baseline

Agent / 04

Build the bootstrap packet

  • `/.agent/skills/bootstrap-clever-work/scripts/bootstrap_clever_work.py`
  • `/scripts/bootstrap_clever_work.py`

Agent / 05

Return the root draft for approval

  • `project-start` payload draft
  • candidate repo/service, candidate lineage

Agent / 06

Tighten execution scope after approval

  • target repo 확정
  • target service 확정
  • `change_id` 필요 여부 확정

Agent / 07

Handoff into implementation repo

  • clone / pull / branch context
  • implementation session으로 이동
CONTEXT

Context / 01

Interpret the work against root rules

  • `/docs/root/index.md`
  • `/docs/root/authority-boundaries.md`
  • `/docs/root/agent-runtime-governance.md`

Context / 02

Resolve lineage, service metadata, deploy baseline

  • `/docs/templates/index.md`
  • `/docs/root/template-harness-governance.md`
  • `/docs/root/deploy-template-governance.md`
  • `/docs/services/service-*/index.md`

Context / 03

Re-read only the service-specific branch of context

  • `/docs/services/service-template.md`
  • target service 문서 갱신 여부 판단
CHANGE CONTROL

Trace / 01

Prepare the root ledger location

  • `/README.md` rules for root id and `change_id`
  • `/.github/ISSUE_TEMPLATE/` as issue form layer

Trace / 02

Create `project-start` as canonical root

  • root canonical identifier = `project-start issue #`
  • `change_id`는 아직 root 식별자가 아님

Trace / 03

Drop into scoped change

  • `/changes/` change unit anchor
  • `/releases/dev|stg|prod/` evidence destination
  • repo / service / rollout scope 확정

Trace / 04

Link PR, rollout, rollback evidence

  • target repo PR 연결
  • release evidence와 final status 갱신
TARGET REPO

Target / 01

Prepare the implementation surface

  • repo clone or refresh
  • branch / worktree / local env 정리

Target / 02

Implement, test, and feed evidence back

  • `/src` or `/app` 구현
  • `/tests` 검증
  • PR / build / rollout 결과를 change-control로 환류
Hard gate first.
구현 착수 전에 반드시 `README`와 `SKILL.md` 레이어에서 쉬운 시작 템플릿을 통과한다.
SSOT is read in two passes.
처음엔 root rule 해석용, 다음엔 target service와 scoped execution을 좁히기 위한 재해석용이다.
Root then scoped execution.
`project-start issue #`가 먼저 열리고, 그 뒤에야 repo/service/`change_id`가 scoped execution으로 내려간다.
